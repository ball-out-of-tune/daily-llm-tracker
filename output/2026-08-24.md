  - **为什么重要**：这在长文本生成场景中尤其关键。当模型思考时间较长时，如果没有心跳，客户端可能会收到连接中断的错误。理解这个机制对于构建稳定的 LLM 应用至关重要。

### 知识点 1：张量并行（Tensor Parallelism）与模型分片
- **是什么**：把一个大的模型权重切成多份，分到多个 GPU 上同时计算，最后合并结果。就像把一本厚书拆成几部分，几个人各读一部分再合起来讲。
- **为什么重要**：当模型太大放不进单张 GPU 时，张量并行是必选项。今天的 commit 中，MiniMax-H3 的 TP 限制（TP1/2/4 支持，TP8 不支持）就是因为在 ConvRot 分组边界处无法正确切分。不懂 TP 的限制，部署时可能莫名报错。
- **动手试试**：

import torch.nn as nn

class ConvRotLayer(nn.Module):
    def __init__(self, dim=256):
        super().__init__()
        # 权重维度是 256 的倍数，TP=8 时 256/8=32，可以切
        # 但如果 group_size=256，TP=8 时每个 shard 只有 32 维，不满足 group 边界
        self.weight = nn.Parameter(torch.randn(dim, dim))

### 知识点 2：权重量化与反量化（INT4/INT8 打包）
- **是什么**：把 FP16/BF16 的模型权重压缩成 INT4 或 INT8，减少显存占用和计算量。INT4 每 2 个权重打包成 1 个字节，INT8 每 1 个权重占 1 字节。
- **为什么重要**：大模型动辄几十上百 GB，不量化根本跑不起来。今天 XPU 的 AWQ INT4 支持就是典型的量化部署。新手不懂打包格式，加载权重时会遇到"维度对不上"的报错。
- **动手试试**：
```python
import torch
import numpy as np

# 模拟 INT4 打包：把两个 INT4 值打包成一个 uint8
def pack_int4_to_uint8(codes):
    """codes: [N, K] int8 (值在 -8~7 之间) -> [N, K//2] uint8"""
    n, k = codes.shape
    assert k % 2 == 0, "K 必须是偶数才能打包"
    packed = torch.zeros(n, k // 2, dtype=torch.uint8)
    # 偶数位放低 4 bit，奇数位放高 4 bit
    packed = (codes[:, 0::2].to(torch.uint8) & 0x0F) | ((codes[:, 1::2].to(torch.uint8) & 0x0F) << 4)
    return packed

# 测试
codes = torch.tensor([[1, -2, 3, -4]], dtype=torch.int8)  # 2 个值打包成 1 个
packed = pack_int4_to_uint8(codes)
print(f"原始: {codes.tolist()}")
print(f"打包后: {packed.tolist()} (每个值占 4 bit)")
print(f"显存节省: {1 - packed.numel() / codes.numel():.0%}")
```
- **预期结果**：你会看到 4 个 INT4 值被压缩成 2 个字节，显存节省 50%。这是 AWQ/GPTQ 量化的核心操作。

### 知识点 3：CUDA Graph 捕获与重放（BCG）
- **是什么**：把一次完整的模型前向计算记录下来（捕获），以后每次推理直接重放，跳过 Python 解释器开销。就像录了一段舞蹈视频，以后每次直接播放视频而不是重新跳一遍。
- **为什么重要**：CUDA Graph 能显著降低延迟（尤其对小 batch 场景）。但今天的 commit 告诉我们：如果推理路径和捕获时不一致（比如 quality=high 时挂了新的融合 kernel），重放就会出错。所以框架必须做安全检查。
- **动手试试**：

### 知识点 4：确定性推理（Deterministic Inference）
- **是什么**：让模型在多次运行中产生完全相同的输出。通过固定随机种子、固定 kernel 的 split 数等方式实现。
- **为什么重要**：在金融、医疗等合规场景，结果必须可复现。今天的 commit 6 把 XPU 的 num_splits 固定为 1，就是为了确保 attention 的归约顺序不变。
- **动手试试**：
```python
import torch

# 非确定性：flash attention 的 split-k 会动态变化
def non_deterministic_attention(q, k, v, num_splits=0):
    """num_splits=0 表示由 kernel 自动决定"""
    if num_splits == 0:
        num_splits = torch.randint(1, 5, (1,)).item()  # 模拟动态决定
    # 模拟 split-k 归约
    scores = torch.matmul(q, k.transpose(-2, -1))
    weights = torch.softmax(scores, dim=-1)
    return torch.matmul(weights, v)

# 确定性：固定 num_splits=1
def deterministic_attention(q, k, v, num_splits=1):
    return torch.softmax(torch.matmul(q, k.transpose(-2, -1)), dim=-1) @ v

q = torch.randn(8, 16, 64, device='cuda')
k = torch.randn(8, 16, 64, device='cuda')
v = torch.randn(8, 16, 64, device='cuda')

out1 = non_deterministic_attention(q, k, v)
out2 = non_deterministic_attention(q, k, v)
print(f"非确定性: 两次结果是否一致? {torch.allclose(out1, out2)}")  # 可能 False

out3 = deterministic_attention(q, k, v)
out4 = deterministic_attention(q, k, v)
print(f"确定性: 两次结果是否一致? {torch.allclose(out3, out4)}")  # True
```
- **预期结果**：非确定性模式下两次运行可能结果不一致，确定性模式则完全一致。这就是为什么生产环境需要固定 num_splits。

### 知识点 5：权重文件覆盖（Weights Override）
- **是什么**：在不改变模型架构配置文件的前提下，只替换模型的权重文件。就像换手机壳而不换手机内部结构。
- **为什么重要**：社区经常发布微调后的权重（比如量化版、蒸馏版），用户只需要替换权重文件就能使用，不需要重新下载整个模型仓库。今天的 VAE 权重覆盖就是典型应用。
- **动手试试**：
```bash

sglang serve --model-path base-model \
  --component-weights-paths.text_encoder \
  path/to/quantized_text_encoder.safetensors
```
- **预期结果**：SGLang 会加载基础模型的配置文件，但用指定的 safetensors 文件替换权重。如果权重文件格式不匹配（比如不是 safetensors），会报错提示。
