- **知识点 1：防御性编程（处理“可能缺失”的数据）**
  - **是什么**：在访问字典或对象属性前，先检查它是否存在（用 `.get()` 代替 `[]`，用 `if x is None` 代替直接使用），避免程序崩溃。
  - **为什么重要**：今天的多个 Bugfix（Commit 7、19）都是因为代码假设“元数据一定存在”，但在 CUDA graph 热身阶段这个假设不成立。不防御，程序就会在启动时崩溃，而非运行时给出友好错误。
  - **动手试试**：
    ```python
    # 糟糕的写法（会崩溃）
    metadata = attn_metadata_map["layer_0"]
    
    # 防御性写法（不会崩溃）
    metadata = attn_metadata_map.get("layer_0")
    if metadata is None:
        print("Skipping layer_0, no metadata available")
        return  # 或者做其他处理
    ```
  - **预期结果**：当你运行一个没有 `"layer_0"` 键的字典时，第一种写法会抛出 `KeyError`，第二种写法会打印提示并安全退出。你掌握了“让程序在异常情况下优雅降级”的技巧。

## 🧪 重要知识点 & 动手实验

### 知识点 1：上下文并行（Context Parallelism）下的状态去重
- **是什么**：当多个 GPU 并行处理同一个请求的不同部分时，部分状态（如 Mamba 状态）在每个 GPU 上都是相同的，只需发送一次，无需重复传输。
- **为什么重要**：在预填充（Prefill）阶段，上下文并行会让每个 GPU 持有相同状态。如果每个 GPU 都传输这些冗余数据，会浪费大量带宽，拖慢整体性能。Commit 9 就是解决这个问题的。
- **动手试试**：
  ```bash
  # 查看 MoRI 连接器中的去重逻辑
  grep -n "_should_skip_cp_replicated_state_transfer" python/sglang/srt/disaggregation/mori/conn.py
  # 查看该方法的定义
  grep -n "def _should_skip_cp_replicated_state_transfer" python/sglang/srt/disaggregation/common/conn.py
  ```
- **预期结果**：你会看到一个条件判断：当 `attn_cp_size > 1` 且 `attn_cp_rank != 0` 且未启用层拆分时，就跳过状态传输。理解了"为什么 rank 0 之外不需要重复发送"就掌握了。

### 知识点 2：在线量化（Online Quantization）与忽略层（Ignored Layers）
- **是什么**：在加载模型时直接对未量化的组件进行量化，同时可以指定某些层（如 attention 层）保持原精度。
- **为什么重要**：不是所有 checkpoint 都预先量化好了。在线量化让你灵活控制"哪些层量化、哪些层保留"，在显存和精度之间找到平衡。Commit 2 为 Diffusion 模型添加了这个功能。
- **动手试试**：
  ```bash
  # 查看量化配置类的定义
  grep -n "ignored_layers" python/sglang/multimodal_gen/runtime/loader/component_loaders/text_encoder_loader.py
  # 查看如何传递忽略层参数
  grep -n "get_quantization_config" python/sglang/multimodal_gen/runtime/loader/component_loaders/text_encoder_loader.py
  ```
- **预期结果**：你会看到 `_configure_encoder_quantization` 函数把 `ignored_layers` 列表传给了量化配置构造函数。理解了"量化不是一刀切"就掌握了。

### 知识点 3：混合量化（Mixed Quantization）与层标记（Layer Markers）
- **是什么**：一个 checkpoint 文件里，不同层使用不同的量化格式（如 NVFP4 和 INT8 混用），通过元数据标记来区分。
- **为什么重要**：模型的不同部分对精度敏感度不同。Attention 层可能用 4 位就够了，但某些线性层需要 8 位。Commit 3 和 19 实现了这种"混合"支持。
- **动手试试**：
  ```bash
  # 查看 NVFP4 配置如何分发到 INT8 配置
  grep -n "set_comfy_layer_markers" python/sglang/multimodal_gen/runtime/layers/quantization/modelopt_quant.py
  # 查看 W4A4 配置如何处理 INT8 层
  grep -n "int8_tensorwise" python/sglang/multimodal_gen/runtime/layers/quantization/configs/kitchen_w4a4_config.py
  ```
- **预期结果**：你会看到 `ModelOptFp4Config` 维护一个 `_comfy_int8_config`，当某层的标记是 `int8_tensorwise` 时，就委托给 `KitchenInt8Config` 处理。理解了"按层分发"就掌握了。

### 知识点 4：推理模式（Inference Mode）与 CUDA Graph 捕获
- **是什么**：PyTorch 的 `torch.inference_mode()` 是一种优化模式，但在此模式下创建的张量不能被 CUDA Graph 捕获时修改。
- **为什么重要**：CUDA Graph 是提升推理性能的关键技术，但它的限制很多。Commit 5 修复了一个因推理模式导致的缓冲区分配 bug，这类问题在性能优化中非常常见。
- **动手试试**：
  ```python
  import torch
  # 在 inference_mode 下创建张量
  with torch.inference_mode():
      buf = torch.empty(1024, dtype=torch.uint8, device='cuda')
  # 尝试在 inference_mode 外修改它
  try:
      buf.fill_(0)  # 这会报错！
  except RuntimeError as e:
      print(f"错误: {e}")
  # 正确做法
  with torch.inference_mode(False):
      buf = torch.empty(1024, dtype=torch.uint8, device='cuda')
  buf.fill_(0)  # 正常
  ```
- **预期结果**：第一次 `fill_` 会报错，第二次正常。理解了这个机制，你就知道为什么 Commit 5 要把分配移出 `inference_mode`。

### 知识点 5：GGUF 格式与文本编码器加载
- **是什么**：GGUF 是一种高效的模型权重存储格式，常用于量化模型。Commit 17 让 SGLang 支持用 GGUF 格式加载文本编码器。
- **为什么重要**：GGUF 文件比原始权重小很多，节省下载和存储空间。但它的加载逻辑复杂，涉及对齐、反量化等细节。
- **动手试试**：

  ```bash
  grep -n "class GGUFConfig" python/sglang/multimodal_gen/runtime/layers/quantization/gguf.py
  ```
- **预期结果**：你会看到 `GGUFConfig` 支持量化嵌入（`supports_quantized_embeddings=True`），这是加载 Qwen3-VL GGUF 文件的关键。理解了"GGUF 是打包+量化"就掌握了。
